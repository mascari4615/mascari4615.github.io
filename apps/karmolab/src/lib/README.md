# `src/lib/` — 도구에 안 매인 공용 부품

> `core/README.md` 가 「위젯은 껍데기, core 는 알맹이」를 적었다. 그 둘 어디에도 안 들어가는 것이
> 여기 온다. 이 파일이 없어서 2026-08-19 에 「lib 이 뭐 하는 폴더냐」를 코드를 세어 답해야 했다.

## 세 폴더 경계

| 폴더 | 정체 | 판정 질문 |
|---|---|---|
| `src/widgets/` | 화면 껍데기. 도구 하나 = 폴더 하나 | 사용자가 이 화면을 여는가? |
| `src/core/` | 도구의 알맹이. 도구와 거의 1:1, 화면 없이 돈다 (MCP 로도 나간다) | 도구 이름 하나를 댈 수 있는가? |
| `src/lib/` | **도구에 안 매인 공용 부품.** 여러 위젯이 나눠 쓴다 | 도구 이름을 못 대는데 둘 이상이 쓰는가? |

위젯끼리는 서로 안 부른다. 둘이 같은 걸 필요로 하면 그때 `lib/` 으로 올린다 —
**「나중에 쓸 것 같아서」 미리 올리지 마라.** 쓰는 곳 하나짜리는 그 위젯 폴더에 둔다.

## 파일 하나가 기본, 폴더는 예외

`lib/` 45항목 중 44개가 파일 하나다. 폴더는 `karmograph/` 하나뿐 —
39파일 257KB 로 혼자 자랐기 때문이다. 폴더로 만들 때는 **왜 파일 하나로 안 되는지**를 그 폴더
README 에 적는다.

## 엔진 이름 (`Karmo*`) — 언제 붙이나

`KarmoGraph`·`KarmoWorld`·`KarmoAccount` 처럼 브랜드 이름을 쓰는 것은 **엔진**이다.
셋 다여야 한다:

1. **표면이 둘 이상** — 위젯 하나만 쓰면 그 위젯의 것이지 엔진이 아니다
   (`karmograph/` = KarmoGraph 위젯 · cockpit · studymap **셋**)
2. **자체 자료형이 있다** — `spec.ts` 같은 「이 엔진의 자료 모양」
3. **이름 붙일 개념이 있다** — 「관계 그래프」·「세계관 데이터」처럼 한 단어로 말할 수 있는 것

**안 붙이는 것**: 배관. `i18n`(쓰는 곳 361) · `tool-url`(32) · `tick`(13) 은 제일 널리 쓰이지만
이름 붙일 개념이 없다. **쓰임이 많다 ≠ 엔진.**

> 주의 — `memo/rules/domain-kl.md:8` 의 「영문 브랜드 조어를 후보로 내지 마라」는
> **사용자에게 보이는 위젯·도구 이름** 룰이다. 모듈 경로에는 안 걸린다.
