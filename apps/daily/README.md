# 오늘의 하나 맞히기 (`/daily/`)

매일 자정(KST)에 문제 하나. 속성 힌트로 좁혀 맞히고, 결과는 **정답이 안 새는 이모지 격자**로 공유한다.
TASK-KAR-202 · 목적 = 방문자 유입(도구가 아니라 *올 이유*).

## 이 앱의 단 하나의 규칙

> **주제를 늘릴 때 코드는 안 고친다.** `data/<주제>.json` 을 넣으면 페이지가 생긴다.

지금 주제: 포켓몬(1025) · 롤 챔피언(173) · 원신 캐릭터(116). 판은 **주제 × 모드** = 6개.

원신은 이 약속을 실제로 시험한 사례다 — 표 한 장(`fetch-genshin.mjs`)만 넣었고 코드는 한 줄도 안 고쳤다.

## 표 검사 (빌드가 막는다)

이름이 겹치면 정답이 여럿이 되어 놀이가 성립하지 않는다. **실제로 두 번 당했다** — 롤은
이벤트 스킨판이 같은 이름으로 또 들어왔고, 원신은 여행자가 원소·성별별로 12개였다.
그래서 빌드가 표를 먼저 본다: 이름 중복 · 빈 속성 · 모르는 `kind` 는 그 자리에서 빌드를 세운다.

그림도 「주소가 적혀 있다」가 아니라 「실제로 받아진다」를 검사가 확인한다 —
실루엣 판은 그림이 전부인데, 밝기만 보는 검사는 그림이 깨져도 통과했다.

## 모드

| 모드 | 주소 | 규칙 | 붙는 조건 |
| --- | --- | --- | --- |
| 속성 | `/daily/<주제>/` | 속성별로 초록·노랑·▲▼ 힌트, 8번 | 언제나 |
| 실루엣 | `/daily/<주제>/silhouette/` | 까만 그림이 틀릴수록 밝아짐, 6번 | 모든 항목에 그림이 있을 때 자동 |

모드마다 **정답이 다르다** — 같은 주제로 하루 두 판이 되는 이유다.
모드는 데이터가 아니라 행동이라 `scripts/build.mjs` 에 산다. 주제 표에는 모드 이야기가 없다.

참고한 것: LoLdle 은 한 주제에 모드를 여럿 굴려 하루 방문 수를 배로 만들었고,
Pokedle 트래픽의 3분의 1이 LoLdle 교차 링크에서 왔다. 그래서 **판이 끝나면 아직 안 푼 판을 건넨다.**

| --- | --- |
| `engine.mjs` | 규칙 전부 — 비교 / 오늘의 정답 / 공유 격자. DOM·fetch 모름. 브라우저와 node 양쪽에서 그대로 돈다 |

| `scripts/lib-table.mjs` | 표를 저장하는 한 곳 — 항목 수가 바뀌면 그 뜻을 말해 준다 |
| `past-row.mjs` | 지난 문제 한 줄 — **빌드와 브라우저가 같은 줄을 그린다** (두 벌로 두면 어긋난다) |
| `past.mjs` / `hub.mjs` | 지난 문제 목록 / 허브. 규칙 판단 안 함 |

| `scripts/lib-pwa-deny.mjs` | 블로그 서비스워커가 우리 주소를 캐시에 담는지 읽는다 (빌드가 막는다) |
| `scripts/check-refresh-delta.mjs` | 표를 새로 받은 뒤 그 변화가 자동으로 넘겨도 되는 크기인지 |
| `scripts/smoke.mjs` | **진짜 브라우저에서 한 판 끝까지 둔다** (playwright 는 이웃 앱 것을 빌려 씀) |

의존성 0 · 빌드 도구 0 은 의도다. 첫 화면이 빨라야 낯선 사람이 안 닫는다.

## 명령

```bash
npm test              # 규칙 시험 (빠름, 의존성 0)
npm run build         # 시험 + dist/ 생성
npm run serve         # dist/ 를 배포와 같은 주소(/daily/)로 띄운다
npm run smoke         # 브라우저에서 한 판씩 (스샷 = .cache/shots/)
npm run smoke:live    # **배포된 사이트**에서 한 판씩

npm run fetch:all     # 표 셋 갱신 — 한국 시각 자정 직후에 (아래 § 참고)
npm run check:fresh   # 표가 원본과 어긋났는지 대조 (네트워크)
npm run check:refresh # 새로 받은 표의 변화가 자동으로 넘겨도 되는 크기인지
npm run check:images  # 표의 그림이 전부 살아 있는지 (1300여 장, 표 갱신 뒤 한 번)
npm run gen:og        # 공유 카드 그림 다시 만들기 (주제·문구 바뀌면)
```

## 주제 하나 더 넣기

1. `data/<id>.json` 을 만든다 — `kind` 는 `number` / `set` / `category` 3종뿐.
   ```json
   { "id": "x", "title": "…", "emoji": "…", "maxGuesses": 8,
     "fields": [{ "key": "gen", "label": "세대", "kind": "number", "near": 1 }],
     "items": [{ "name": "…", "img": "…", "gen": 1 }] }
   ```
   `near`(절대 오차) 나 `nearRatio`(비율)를 주면 가까울 때 노랑이 뜬다.
2. 그림이 큰 것·작은 것 두 벌이면 표에 `art: { from, to }` 한 줄 (위 § 참고). 없으면 안 써도 된다.
3. `npm run build` — 끝. 허브에도 자동으로 걸린다.

이름 찾기는 **첫 자음만 쳐도** 되도록 엔진이 알아서 한다 (「ㅍㅋㅊ」 → 피카츄). 표에 따로 적을 것은 없다.

## 표가 낡는 것 — 조용히 안 늙게

표는 가만두면 낡는다. 새 챔피언·새 포켓몬이 나와도 우리 표엔 없어서 그 이름은 자동완성에도
정답에도 안 나온다 — 사람은 「낡은 사이트」로 읽고 떠나는데 우리는 아무 신호도 못 받는다.

- 표마다 `fetchedAt` 이 박힌다. **180일 넘으면 빌드가 선다** (150일부터 경고).
  멈추기만 하고 방법을 안 알려 주면 방해일 뿐이라, 메시지에 고치는 명령까지 적는다.
- `npm run check:fresh` — 원본에 물어 실제 항목 수를 대조한다. 배포에선 안 돈다
  (바깥 서버가 잠깐 말썽인 것으로 배포를 세울 이유가 없다).
- 세는 규칙은 표 만들 때와 **같은 파일**을 쓴다 (`scripts/rules-*.mjs`). 따로 적었더니
  116 대 118 로 갈려 거짓 경보가 났다.

## 표 갱신 — 이제 스스로 돈다

**손으로 안 해도 된다.** `daily-table-refresh.yml` 이 **주 1회, 한국 시각 월요일 00:10** 에 돈다.

받고 → 변화 크기 보고(`check:refresh`) → 시험·페이지 생성 → 그림 1300여 장 전수 → 브라우저 검사 →
공유 카드 다시 그리기 → 바뀌었으면 커밋. **표가 이상하게 줄면 커밋을 접고 빨갛게 남는다**
(늘어나는 건 15%까지, 줄어드는 건 3%까지만 자동으로 넘긴다). 초록인데 아무것도 안 바뀐 것은
새 챔피언이 없었다는 뜻이라 정상이다.

손으로 돌려야 할 때(새 주제를 넣었거나 급할 때)는 같은 순서를 따르면 된다:
`fetch:all` → `check:refresh` → `check:images` → `gen:og` → `build && smoke`.
`npm run fetch:all` 이 지금 몇 시인지 보고 지금 돌려도 되는지 말해 준다.

### 왜 하필 자정 직후인가

**항목 수가 바뀌면 그날 이후의 정답 순서가 통째로 다시 섞인다.** 순열이 항목 수를 씨앗으로 쓰기 때문이다.
한낮에 갈아끼우면 이미 두던 사람의 정답이 바뀐다. 자정 직후엔 두던 사람이 거의 없다.
새 챔피언은 몇 달에 한 번이라, 항목 수를 고정하는 것보다 이 시각을 지키는 쪽이 싸다.

## 그림이 두 벌인 주제 (`art`)

포켓몬 그림은 **한 장에 300배 차이가 난다** — 도트 0.5~2KB, 공식 일러스트 140~200KB.
목록·자동완성·추측 줄에 큰 것을 쓰면 두 글자만 쳐도 1MB 가 넘게 나간다 (실제로 그랬다).

- `items[].img` = **작은 것.** 목록·자동완성·추측 줄·지난 문제 전부 이걸 쓴다.
- 표의 `art: { from, to }` = 작은 주소에서 큰 주소를 만드는 **규칙 한 줄.**
  항목마다 큰 주소를 넣으면 표가 90KB 부는데 실제로 쓰는 건 하루 한 장이다.
- 큰 것을 쓰는 자리는 둘뿐이다: **실루엣 판**과 **답을 공개하는 순간.**
- `art` 가 없는 주제(롤·원신)는 `img` 하나로 돈다.

지난 문제의 답 그림은 **가려진 동안 아예 안 받는다** — 열 때, 그것도 화면에 들어온 것만 받는다.

## 난이도 — 짐작하지 말고 잰 값

「1025마리 중 하나를 8번 안에」가 너무 빡빡해 보였지만, 힌트를 완벽하게 쓰는 플레이어를
120판 돌려 재 보니 그렇지 않았다.

| 주제 | 항목 | 평균 | 중앙 | 상위 90% | 최악 | 8번 내 성공 |
| --- | --- | --- | --- | --- | --- | --- |
| 포켓몬 | 1025 | 3.1회 | 3 | 4 | 6 | 100% |
| 롤 | 173 | 2.5회 | 2 | 3 | 4 | 100% |
| 원신 | 116 | 2.8회 | 3 | 4 | 5 | 100% |

(롤 속성을 실제 스탯으로 갈아탄 뒤 다시 잰 값이다. 속성을 바꾸면 이 표도 다시 재야 한다.)

속성 6개가 주는 정보량이 커서 **정보는 모자라지 않는다**. 사람이 막히는 지점은 정보가 아니라
*그 조건에 맞는 이름이 떠오르지 않는 것*이다. 그러니 시도 횟수를 늘려도 별 효과가 없다 —
난이도 이야기가 다시 나오면 여기부터 볼 것.

## 속도 — 짐작하지 말고 잰 값

느린 폰(3G급 회선 + CPU 4배 느림)에서 실주소로 재 봤다. **고칠 것이 없어서 안 고쳤다.**

| 주소 | 화면 뜸 | 쓸 수 있기까지 | 가장 큰 그림 | 받은 양 |
| --- | --- | --- | --- | --- |
| `/daily/` | 1.05초 | 1.11초 | 0.63초 | 11KB |
| `/daily/pokemon/` | 0.89초 | 1.27초 | 0.64초 | 39KB |
| `/daily/lol/` | 0.79초 | 1.06초 | 0.59초 | 22KB |

포켓몬 표가 원본 219KB 라 커 보이지만 압축되면 21KB 다. 「무거우니 쪼개자」가 나오면 여기부터 볼 것.

## 계측 — 무엇을 재나

목적이 유입인데 유입을 못 재면 개선이 장님이다. 사이트가 이미 쓰는 GoatCounter 를 그대로 쓴다
(쿠키·개인 식별자 없음). 깔때기는 **방문 → 첫 수 → 끝냄 → 공유** 넷이다.

- 첫 수는 「시작점 단추」와 「직접 침」을 갈라 센다 — 그 장치가 먹히는지 보려는 것이다.
- 연습 방문은 오늘 판과 따로 센다. 합치면 「오늘 몇 명이 열었나」가 부푼다.
- **정답은 절대 안 실린다.** 실리면 그걸 보고 그날 답을 알 수 있다 — 검사가 그 한 줄을 지킨다.
- 내 기계(localhost)에서는 아예 안 보낸다. 그래서 검사는 가짜 도메인으로 들어가 켜진 쪽을 본다.

## 검색 노출

사이트맵을 따로 만들지 않는다. 블로그 루트의 `/sitemap.xml` 이 이 폴더의 html 을 이미 거둬 간다
(실측으로 확인했다). 판이 늘면 다음 배포에서 저절로 들어간다.

`/daily/<주제>/past/` 는 「오늘의 정답」을 검색하는 사람을 받는 자리다 — 오늘 답은 절대 안 넣는다.

## 검사가 지키는 것 (고치기 전에 읽을 것)

숫자보다 **무엇을 지키는지**가 중요하다. 아래 것들은 한 번씩 실제로 깨졌던 자리다.

| 지키는 것 | 어디서 |
| --- | --- |
| **오늘 답이 어디로도 안 샌다** — 공유 글·지난 문제·계측 어디에도 | 규칙 + 브라우저 + 실주소 |
| 오늘·미래 날짜로는 연습이 안 열린다 (열리면 답이 샌다) | 규칙 |
| 한 주기 안에 정답이 안 겹치고, 모드가 다르면 답도 다르다 | 규칙 |
| 표에 같은 이름이 두 번 들어가면 빌드가 선다 | 빌드 |
| 블로그 페이지가 우리 주소를 가져가면 빌드가 선다 | 빌드 |
| 그림이 「주소만 적힌」 게 아니라 실제로 받아진다 | 브라우저 |
| 색·화살표로만 알리지 않는다 (같은 내용이 말로도 남는다) | 브라우저 |
| 누르는 자리가 손가락만 하다 (자로 잰다) | 브라우저 |
| 조용히 실패하지 않는다 — 표·그림 못 받음, 없는 이름, 자정 넘김 | 브라우저 |
| 배포된 것이 **우리 것**이다 (200 만으로는 모른다) | 실주소 |
| 지난 문제의 답이 **HTML 원문**에 박혀 나간다 (로봇은 자바스크립트를 안 돌린다) | 브라우저 + 실주소 |
| 내부 링크가 전부 닿는다 (깊이가 판마다 달라 상대 경로가 잘 틀린다) | 브라우저 |
| 그림이 가볍다 — 자동완성·지난 문제가 폰 데이터를 통째로 먹지 않는다 | 브라우저 |
| 저장소가 아예 막힌 브라우저에서도 세 화면이 다 열린다 | 브라우저 |
| 접근성 바닥 — alt·단추 이름·제목 단계·이름표 | 브라우저 |
| 하는 법 설명이 지금 있는 기능을 다 말한다 | 브라우저 |

## 스스로 도는 것 (내가 안 돌려도)

| 언제 | 무엇 | 빨개지면 |
| --- | --- | --- |
| `apps/daily/**` 밀어 넣을 때 | 브라우저 검사 250여 개 (`daily-browser-check.yml`) | 배포는 나간다 — 대신 반드시 보이게 둔다 |
| 6시간마다 | 실주소에서 한 판씩 (`daily-live-check.yml`) | 깃허브가 메일. 배포 중 헛나감은 한 번 더 보고 판정 |
| 월요일 00:10 (KST) | 표 새로 받기 (`daily-table-refresh.yml`) | 커밋을 접는다 |

실주소 점검이 없던 때는 **내 기계에서만** 돌 수 있었다 — 내가 안 돌리면 사이트가 조용히 죽어도 몰랐다.

## 배포에서 걸리는 곳

- `pages-deploy.yml` 이 `npm run build` 후 `dist/` 를 `apps/blog/daily/` 로 복사한다. 시험이 깨지면 배포도 안 나간다.
- 루트 Chirpy 서비스워커가 cache-first 라, `_config.yml` 의 `pwa.cache.deny_paths` 에 `/daily` 를 넣어 뒀다.
  **빼면 방문자에게 어제 문제가 계속 나온다.**
- 자산 주소에 빌드 도장(`?v=…`)이 붙는다 — 캐시가 옛 파일을 붙들지 못하게.
- **블로그 쪽 파일 이름이 곧 주소다.** `apps/blog/_tabs/daily.md` 를 그냥 만들면 Jekyll 이 그걸
  `/daily/` 로 내보내 **게임 허브를 통째로 덮는다** (2026-08-07 실제 사고 — 허브가 자기 자신으로
  넘기는 무한 새로고침이 됐고, 응답은 멀쩡한 200 이라 주소만 찔러서는 못 잡았다).
  그런 파일에는 `permalink:` 를 따로 박는다. 지금은 빌드가 이 겹침을 먼저 막는다.
- 여러 세션이 같이 밀어 넣으면 **새 push 가 앞 배포를 취소시킨다.** 사이트가 깨진 걸 고치는
  중이라면 그 판이 끝날 때까지 push 를 멈추는 편이 빠르다.

## 안 한 것 (일부러)

로그인 · 서버 저장 · 전체 랭킹. 사람이 온 뒤에 붙인다.
