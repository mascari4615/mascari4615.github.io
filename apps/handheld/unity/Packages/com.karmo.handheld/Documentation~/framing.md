# 화면 비율. 보이는 것 = 나가는 것

> 코드: `HandheldRig.EffectiveAspect` / `EnsureRenderTexture`

## 화면 비율. 보이는 것 = 나가는 것

방송은 16:9 로 나가므로 **렌더도 16:9 고정**이 기본이다. 폰이 어떤 비율을 알려주든
(세로 0.46, 가로 2.17, 정사각 1.0) 렌더는 `1280×720` 하나로 나온다.

폰 화면에는 **레터박스**로 뜬다. 꽉 채우면(cover) 프레임 가장자리가 잘려 나가
보이는 것 ≠ 나가는 것이 되기 때문이다. 뷰파인더는 송출 프레임과 같아야 한다.

### 주체가 다른 두 가지

| 무엇 | 누가 정하나 | 왜 |
| --- | --- | --- |
| **송출 비율** (16:9 / 9:16) | **조종석** (감독) | 방송으로 나가는 프레임. 카메라맨이 바꾸면 안 된다 |
| **그립** (눕혀 잡나 세워 잡나) | **폰** (카메라맨) | 손에 든 사람의 몸 편의. 나가는 그림과 무관하다 |

그립은 **시작 화면에서 한 번만** 고른다. 누워서 / 세워서. 찍는 도중에 바뀌면
송출 프레임이 90° 튀어 방송 사고가 되므로, 세션 중에는 바꾸는 손잡이 자체가 없다.

**AR 세션은 진입 시점의 화면 방향으로 잠긴다.** 기기 자동회전을 켜도 세션에 들어간 뒤에는
페이지가 안 돈다 (2026-08-20 실기 확인: 가로로 들어도 `∠0 portrait`). 그래서 눕혀 쓸 거면
**눕힌 채로 시작을 눌러야** 한다. 시작 화면이 지금 방향을 읽어 그 사실을 알려주고,
어긋나면 경고한다. 진입 순간의 실제 방향이 고른 것과 다르면 **현실을 따른다**
(가로로 들어갔는데 롤을 걸면 그림이 옆으로 눕는다).

- **누워서**. 롤 0. 16:9 가 그대로 꽉 찬다. 세로로 **2초 넘게** 들고 있으면
  돌려서 잡아라 안내가 뜬다 (카메라 워킹 중 롤이 세로를 스쳐 가는 건 의도된
  동작이라 그때는 안 뜬다).
- **세워서**. 폰이 `gripRoll=90` 을 보내 **카메라 롤을 90° 같이 돌리고**, 화면도
  −90° 돌려 되받는다. 둘이 짝이라 겨냥 방향과 그림이 어긋나지 않는다(롤은 전방 축
  회전이라 조준 자체는 안 변한다). 16:9 프레임이 폰 긴 쪽을 꽉 채운다.

가로로 들면 UI 도 가로에 맞게 옮겨간다. 버튼은 오른쪽 위로 세로 배열, 통계 칩은
왼쪽 위, 스틱 구역은 아래 모서리. 세로 배치 그대로 두면 하단 버튼 바가 스틱 구역과
겹친다.

화면**만** 90° 돌려 채우는 길은 안 했다. 카메라가 안 굴렀는데 그림만 돌리면 폰을
오른쪽으로 밀 때 그림이 위로 가는 **거짓 뷰파인더**가 된다.

대가가 있다. 세로 폰 비율일 때는 `332×720` 이라 6KB/장이었는데, 16:9 는 `1280×720`
= 픽셀이 4배라 **35KB/장**이고 인코딩이 병목이 된다.

| 경로 | fps | 대역폭 |
| --- | --- | --- |
| 로컬 720p 16:9 | 39.5 | 1.4 MB/s |
| 터널 너머 720p 16:9 | 31.5 | 862 KB/s |

무거우면 조종석에서 **세로 해상도**를 540, 480 으로 내려라 (화질 ↔ fps 저울).
